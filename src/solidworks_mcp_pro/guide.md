# SolidWorks MCP PRO agent guide

This server extends the pinned solidworks-mcp 0.19.0 CAD engine. Read solidworks://guide for native geometry conventions. Millimetres/degrees/kg. Create new documents for new designs; preserve the user's existing documents. In v0.6.0 the full profile publishes 123 tools (88 inherited CAD plus 35 PRO); compact publishes 14 workflows and retrieves exact native schemas through pro_tool_help. Native steps still run in pro_run_plan.

Start with pro_connection_doctor to establish this running server's identity and actual tool profile. The offline --connection-doctor and connection_doctor module never establish another client's live connection. --doctor remains a dependency-only check. Source/package version mismatches must be corrected through installation, not hidden. No doctor call launches configured commands or starts CAD.

Use pro_validate_design(document_path, assertions) to check explicit requirements on the exact active saved part/assembly. An assertion has a unique id, kind, unit, abs_tolerance and expected or min/max. Supported kinds: dimension (exact name, mm/deg), mass (kg), volume (mm3), bbox_size (axis x/y/z, mm), distance (exact component_a/component_b, mm). Relative tolerance defaults to zero. ok=true means the requested checks completed; passed=true additionally means every requirement held. Failed conditions remain failed; unknown native measurements are never pass. The scan does not rebuild, save, activate documents or change selection. Distance is unsigned and zero does not establish interference-free fit. State comparison covers the top model metadata and file stat, not a full recursive geometry snapshot.

Use pro_variant_study(document_path, request_id, parameters, dry_run=true) before execution. Supply one or two exact dimensions with mm/deg units and explicit value arrays; the Cartesian product is limited to 16. dry_run writes nothing. Execute with dry_run=false and the same request_id after reviewing the plan. A source must be a saved self-contained .sldprt, clean if open; external references are refused. Every candidate starts from an independent copy, has its dimensions read back, rebuild and feature errors checked, then mass/volume/tight bounds measured. Optional assertions use the same design contract. The lightest valid candidate is ranked first; this is not an optimizer or a strength analysis. Source bytes and open-source metadata are rechecked, owned copies closed, and the prior active document restored. Reports include CSV/JSON paths and resource URIs.

Use pro_shot_pack(document_path, request_id, shots) for 1..12 explicit native product shots. A shot has unique ASCII name, view, optional aspect square/landscape/portrait, optional width+height together, and optional zoom_factor. custom requires from_direction and optional up_direction. Previews preserve the exact requested aspect; final PNGs, a contact sheet and a JSON manifest are generated from the current scene/materials. It does not save, recolor, pose or infer explosion. Original model-view camera restoration is verified before releasing the lease. A named active camera is refused by the existing checkpoint guard. Image integrity is not aesthetic acceptance. The default pro_result image is the contact sheet; select artifact_id for a particular final.

For stable portrait framing choose pro_shot_pack(render_route="project"). It reads verified native bounds, exports one part-grouped SVPJ (2026+) and renders owned copies through the installed Offline Renderer with explicit perspective fit cameras. Supported directions are iso/isometric/front/back/left/right and custom with world-Y up; zoom_factor 0.25..1. Other directions/up vectors/crop zooms are rejected before native work. Both previews and finals keep the exact target ratio, and the fit uses the smaller horizontal/vertical half-FOV. Project-copy ground shadows are on and reflections off. The default render_route="addin" uses model-view transfer, which can crop portrait images regardless of local viewport zoom; show the actual image. No silent route fallback is permitted or claimed.

Prefer pro_render_job(document_path, request_id) for diagnosed preview/final output. It uses the exact active saved model, current scene and explicit optional RGB assignments. Default preview is 960x540/50 passes; final 1920x1080/200; denoiser on. quality=4k selects 3840x2160 final. mode=exploded requires explicit top-level component position_mm and rotation_deg transforms, at most 128. No disassembly is inferred. Temporary matrices and model-view camera are restored and verified; requested colors remain unsaved. No automatic save or repair occurs. Named cameras are refused before mutation. Native RGB readback does not prove Visualize P2M fidelity; show the real final image for review.

Use pro_diagnose(document_path) for read-only active-model health. Warnings, errors and unknown checks are distinct. deep=true adds body/interference checks and may mark an unchanged assembly dirty through native Done(); that specific verified side effect is reported and never cleared/saved. pro_repair(action=plan, document_path) creates detached steps without changing CAD; only a separate user instruction authorizes pro_repair(action=apply, plan_id). Stale plans and repeated attempts are guarded. Never guess dimensions, delete mates or substitute missing references.

Compact/new-workflow results are concise; full evidence is available through details_uri or pro_result(operation_id,kind=details). Poll pro_operation with wait_seconds=20. New-workflow polls are image-free; deliver the real final once with pro_result(operation_id,kind=image). Retrieval never repeats CAD. Request replay protects only this server process; inspect before resubmitting after a restart. For legacy tools, get_status attaches to the running application without creating a document.

For geometry: plan → pro_run_plan(dry_run=true) → execute with a unique request_id → pro_verify_volume → pro_capture_view. A dry run validates every step's schema, documented input relationships and output targets before any mutation; it does not prove geometry is feasible. Stop on the first failed measurement. Reported failed rebuilds or broken features become CAD_POSTCONDITION_FAILED and stop subsequent steps. Plan failure does not undo previous successes.

For photorealistic rendering: pro_visualize_status → pro_visualize_render(request_id, width, height, passes, image_format, denoiser) → pro_operation(operation_id). The actual SOLIDWORKS Visualize add-in renders the current model's appearances and scene. Add-in API requires SolidWorks 2025+ and appropriate installed/licensed Visualize. Grouped native SVPJ export uses 2026+; appearance grouping can use the 2025 API. Never describe an offline mesh preview or SolidWorks viewport as a photorealistic Visualize render.

Long calls return a running operation_id. Poll it; never blindly retry after timeout. Calls already submitted to COM cannot be force-aborted by cancelling an MCP request. Use pro_operations if an ID was lost. Request deduplication is in-process, not persistent across restarts. At session capacity, finish and inspect operations before restarting. Normal stdio EOF drains tasks; force-killing the server does not.

Use pro_visualize_appearances(document_path, assignments, dry_run=true) to inspect validated exact component targets and their current appearance collections first. Then dry_run=false applies local .p2m render appearances to the active saved assembly's current display state. Optional color_rgb [0..255, 0..255, 0..255] requests a color override, but a native .p2m material can reset that color during application. A mismatched read-back fails after application; arbitrary custom RGB support is not guaranteed. Work on an authorized render copy, validate the returned assignment results, then render a small material check. This changes assembly appearances without saving or modifying referenced part files. A failed batch can leave partial changes; inspect its report before retrying.

Use pro_visualize_export to create an .svpj, then pro_visualize_open_project(path) to send an existing local project to the Visualize application through the native IVisualizeAddinManager2.LaunchVisualize API (2026+). The open call does not require an active CAD document. No screen clicks, shell or arbitrary command execution are involved. launch_requested confirms native API acceptance only; project_loaded=null means the requested document's loading has not been independently verified. Do not describe a generic window-title change or GPU-device initialization as proof of that specific project's loading.

For studio lighting, inspect pro_visualize_scene(document_path, dry_run=true), then apply an existing local .p2s scene and/or .hdr/.exr environment. Inserting a .p2s requires RealView; the tested GPU/installation could not enable it and insertion failed, while direct HDRI assignment to the existing scene was verified. Do not assume preset insertion is supported on every GPU. environment_rotation_deg is 0..360 degrees. Optional floor_shadows and floor_reflections request native floor settings; reflections cannot be requested with shadows disabled. The native API can reject or couple floor changes. A failed readback is reported as failure, potentially after partial changes, rather than guaranteed floor support. Disable up to 64 lights by unique exact disable_light_names or by disable_light_ids from the fresh native inventory when names are duplicated; do not supply both nonempty lists. Inserting a scene can replace light IDs, so scene_path and a nonempty disable_light_ids list require separate calls with a fresh inspection between them. Disabling targets both native viewport and render-light flags. An HDRI containing studio light panels supplies softbox-style illumination; this tool does not create a separate Visualize softbox light object. Scene changes are not automatically saved; check a native preview before final rendering.

Use background_type="environment", "plain" or "gradient" to select the native backdrop. hdri_path defaults the backdrop to environment unless background_type explicitly overrides it. background_top_rgb controls a plain or gradient background; background_bottom_rgb is valid only for a gradient. Colors are three integers 0..255. Native HDRI lighting and a separate plain backdrop may transfer differently to Visualize, so verify the rendered result. PhotoView RenderingBrightness is not exposed as a public MCP scene argument: a native 0.8-to-2.0 readback change produced no demonstrated Visualize exposure change in the controlled render comparison. Do not advertise native PhotoView brightness as a verified Visualize exposure control.

Use pro_visualize_camera(document_path, action="inspect") to read active model-view framing. action="apply" sets a standard view or view="custom" with from_direction pointing from the model toward the camera and optional up_direction (default [0,1,0]); these are directions, not positions in millimetres. Use nonzero, nonparallel vectors. fit=true optionally fits the model, then zoom_factor (0.25..2) adjusts its framing. perspective=true enables native perspective; object_sizes_away (1..20) is distance in object sizes, not a focal length. This edits the native active view rather than creating a named camera feature. No automatic save or depth-of-field/lens control is implied. Inspect the actual Visualize preview to confirm transfer of composition.

pro_capture_view and successful render polls return inline image content. Show these real images when the host supports them, otherwise the returned local paths. Offline HTML resources from pro_preview_model/pro_preview_stl are standalone browser viewers; a host's optional visualization plugin is separate and is not automatically invoked by this server. The HTML needs no network/CDN.

STL has no unit metadata; coordinates assumed mm. Mesh volume is reported only for watertight consistently oriented nondegenerate triangles. Self-intersections and disconnected-shell winding need independent inspection; topology checks alone do not prove manufacturability.

PRO instances share a cross-process CAD lease but unrelated SolidWorks automation does not. Avoid controlling the same CAD session from multiple independent servers. Native operations preserve upstream checks; there is no raw arbitrary VBA/Python/shell execution tool.

Output files use unique names. Only registered server-produced files are readable as solidworks-pro://artifact resources. Large files remain local paths. The audit contains plan outcomes and timings without full arguments.

Native save_part, save_assembly, export, screenshot and make_drawing refuse an existing normalized output path unless overwrite:true is supplied. Use a new path or obtain task authorization to replace the existing file. Per-component exports require an empty destination directory by default because SOLIDWORKS chooses the component filenames. These pre-execution checks are not atomic against unrelated applications writing at the same time.
